두 조건 모두 길가 차량이나 고정 장애물만 진행 공간을 점유하면 같은 대상의 R4를 근거로 통과 가능성 확인을 요구한다. 보류는 허용한다. 다른 Actor도 함께 점유하면 그 Actor에 대한 양보 또는 보류도 필요하다. 전체 대응 규칙, P/A/U 정의와 출력 Schema는 두 조건에서 같다. 기존 Pilot Base와 여섯 예측은 과거 실행 기록으로 보존한다.

## 확인할 가설
Draft에서 002·004·005의 R1은 P이고 기존 예측은 A였다. 접지 재확인 문구가 독립 Dev의 R1 점유 누락을 줄이는지 살핀다. 세 장의 라벨과 원인은 검토 중이다. 이미지 번호나 Draft 근거는 프롬프트에 넣지 않는다.

## 비교 방법
Pilot과 장면이 겹치지 않는 동일 Dev에서 A와 B를 짝지어 비교한다. 점유 P, 비점유 A, 접지 경계가 불명확한 U를 포함한다. 모델 revision, NF4·BF16, 입력 크기, seed 42, greedy 생성, 최대 4096 token, Parser와 평가기 버전을 고정한다. 입력은 이미지와 진행 의도이며 GT와 평가용 geometry는 백엔드에서만 사용한다.

주 지표는 검수된 R1=P 중 P로 답한 수와 비율이다. R1=A 중 P 오탐, R1=U 중 A 단정도 각각 분모와 함께 기록한다. 같은 장면에서 개선·악화된 건수와 형식 실패를 함께 보고한다. 분모가 없으면 N/A로 둔다. 완전 검수된 대응 규칙이 있는 사례에서만 R4 통과 확인과 혼합 점유 Actor 대응 누락을 비교한다.

## 실행 전 확인
Dev 목록, Reviewed 범위, 평가기 버전과 채택 기준을 확정한다. 별도 실행 경로에서 두 시스템 메시지가 각 파일과 일치하는지 확인하고 같은 환경에서 새 Run ID를 부여한다. 후보 문구와 실험 설계는 팀 검토 대기이며 결과는 미실행이다.
