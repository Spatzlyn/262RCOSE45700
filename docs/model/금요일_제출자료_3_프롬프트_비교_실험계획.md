# 금요일 제출 자료 3 근거 연결과 P/A/U 판단 개선 실험안

담당 하경흠 · AI 모델/알고리즘

상태는 실험 설계이며 아직 실행하지 않았습니다. 금요일 2026년 11월 13일 오전 10시 KST에는 설명 가능한 초안과 기존 오류 증거를 제출합니다. 일요일 11월 15일에는 공통 6장의 실제 오류를 바탕으로 보완할 계획이며 교수님 피드백에 따라 범위를 조정합니다. 새 학습 결과는 이번 주 필수 산출물이 아닙니다.

[중국어 원문](friday_03_prompt_ab_plan.md)의 한국어 정리본입니다. 중국어 문서와 실험 자료는 변경하지 않았습니다. **이번 검증에서 확인**은 원문 검증 당시 실제 확인한 결과, **기존 기록**은 원 실험을 재실행하지 않고 읽은 내용, **추가 확인 필요**는 증거 부족, **가설**은 가능한 설명, **향후 계획**은 아직 수행하지 않은 작업입니다. 번역 중 새 실험은 실행하지 않았습니다. 명령과 근거는 [검증 보고서·중국어](verification_report.md)에 있습니다.

## 관측한 두 가지 오류

기존 예시는 dry_run_v1 고정 커밋 `ef1ed254d4bbcb15d66c0ec96a02861ef1e7c681`에서 확인했습니다. 실제 Schema는 integrated-sample-0.2의 track1/track2/track3 구조이며 장면 속성은 track1.attributes입니다. PDF의 간략 JSON 예시로 원 구조를 대체하지 않습니다. Strict JSON/Schema는 통과했지만 관계 매칭은 0/4, Action=False입니다. 독립 Draft 장면은 1개이며 Human Reviewed 장면은 0개입니다. 공식 Benchmark 결과를 제시할 수 없고 원 데이터는 변경하지 않았습니다.

첫 관측은 **이번 검증에서 확인**한 출력 사실입니다. Adapter 없는 Base NF4 `nf4_prompt_v1_first`가 형식 Prompt 수정 후 생성한 첫 응답에서 객체 5개 중 4개가 Draft와 매칭되었으나 R1부터 R4는 모두 A이며 근거와 regions가 비어 있습니다. Draft R3는 P이고 근거에 모델이 검출한 주요 차량이 포함됩니다. 따라서 누락만으로 설명되지 않을 가능성을 검토하되, 단일 Draft로 일반적인 원인을 증명하지 않습니다.

두 번째 관측은 R2의 Draft U와 예측 A가 다르다는 점입니다. 정보 부족을 확인된 부재와 혼동했다는 설명은 **가설**입니다. 출입구 경계나 객체 위치가 불충분한 U와 충분히 관측한 뒤의 A를 구분해야 하지만 먼저 Draft 라벨의 사람 검수가 필요합니다.

근거는 [실제 예측](https://github.com/Spatzlyn/262RCOSE45700/blob/ef1ed254d4bbcb15d66c0ec96a02861ef1e7c681/kakao_dryrun/representative_inference/parsed_output.json), [진단 기록](https://github.com/Spatzlyn/262RCOSE45700/blob/ef1ed254d4bbcb15d66c0ec96a02861ef1e7c681/kakao_dryrun/representative_inference/metrics.json), 규칙·GT·모델 문제를 구분한 [기존 개선 계획](https://github.com/Spatzlyn/262RCOSE45700/blob/ef1ed254d4bbcb15d66c0ec96a02861ef1e7c681/kakao_dryrun/reports/improvement_plan.md)입니다.

## 원인 가설

모델이 스스로 출력한 Object/Region, 역할과 관계를 안정적으로 연결하지 못하고, 결정하기 어려운 관계를 A로 출력하는 경향이 있을 수 있다는 가설입니다. 검수한 독립 장면에서 확인해야 하며 확정된 원인으로 쓰지 않습니다.

**기존 기록**에서 required_fields_v1은 필수 필드와 Strict JSON 형식을 주로 개선했으며 관계 의미의 개선은 증명하지 못했습니다. reports/qlora_audit.md에 따르면 기존 QLoRA는 같은 Draft 한 장면으로 진행한 5-step smoke입니다. audit/training_verification.json에는 loss가 1.1774322986602783에서 1.1210620403289795로 감소하고 adapter tensor 132/132개가 갱신되었으며 saved_state_exact=true라고 기록되어 있습니다. runs/qlora_prompt_v1_first/adapter_reload_check.json은 exact_loaded_state_match=true입니다. 해당 필드를 다시 읽었지만 학습이나 로딩을 재실행하지 않았고 독립 장면 성능 개선을 증명하지 못합니다.

기존 증거는 [학습 감사](https://github.com/Spatzlyn/262RCOSE45700/blob/ef1ed254d4bbcb15d66c0ec96a02861ef1e7c681/kakao_dryrun/reports/qlora_audit.md), [학습 검증](https://github.com/Spatzlyn/262RCOSE45700/blob/ef1ed254d4bbcb15d66c0ec96a02861ef1e7c681/kakao_dryrun/audit/training_verification.json), [adapter 재로드 기록](https://github.com/Spatzlyn/262RCOSE45700/blob/ef1ed254d4bbcb15d66c0ec96a02861ef1e7c681/kakao_dryrun/runs/qlora_prompt_v1_first/adapter_reload_check.json)입니다.

## 하나의 실험과 변경할 요소

**향후 계획**으로 Prompt A/B 대조를 진행합니다. 대조 A는 prompts/modified_system_full.txt를 고정합니다. Required_fields_v1이 이미 포함되어 있으므로 중복 추가하지 않습니다. 실험 B는 A에 근거 확인과 P/A/U 구분을 위한 전체 Prompt 개선 묶음만 추가합니다. B가 더 좋아져도 묶음 전체의 효과로만 해석하고 특정 한 문장이 유효했다고 결론 내리지 않습니다. 이후 항목별 제거 실험으로 구분할 수 있습니다.

두 조건 모두 google/gemma-4-E4B-it, revision 4ecc2ba63bcac23ba4a767fc87025b1450f84c9c, Base NF4 double quant, BF16 compute, batch=1, soft-token budget=280, seed=42, do_sample=false, max_new_tokens=4096, enable_thinking=false, cpu_offload=false를 사용합니다. Adapter를 로드하지 않습니다. 이미지 처리, 입력, Schema, Evaluator와 독립 Dev 장면 및 검수 버전을 동일하게 유지합니다. 전체 실행 계획은 자료 2와 같습니다. 환경, 추론 입구와 규칙은 아직 확보·확정이 필요하며 실험은 실행하지 않았습니다.

모델, 해상도, 규칙, reference 라벨이나 학습을 동시에 바꾸지 않습니다. 규칙/GT를 수정해야 한다면 먼저 새 버전을 고정하고 동일한 새 버전에서 A/B를 비교합니다. 기존 결과도 보존합니다.

다음은 B에 추가할 한국어 Prompt 초안입니다. 중국어 원문의 한국어 Prompt를 그대로 보존했습니다. 확정된 규칙 버전에 맞추어 실행 전에 다시 검토해야 하며 이미 실험한 Prompt가 아닙니다.

```text
각 관계는 독립적으로 판정하십시오. 먼저 이번 출력에서 선언한 Object와 Region 중 해당 관계의 근거를 확인하십시오. roles와 object_ids, region_ids는 같은 근거를 가리켜야 합니다.
선언한 Object와 Region이 충분하지 않다면 원본 이미지에서 관련 근거가 누락되었는지 다시 확인하십시오.
P는 관계가 성립하는 관측 근거가 있을 때 사용하십시오. A는 필요한 범위를 충분히 확인했고 관계가 성립하지 않을 때 사용하십시오. 입력만으로 필요한 위치나 경계를 판단할 수 없으면 U를 사용하십시오. 단순히 보이지 않는다는 이유만으로 A를 선택하지 마십시오. 판단 가능한 경우를 U로 회피하지 마십시오.
가림을 만든 Object와 가려진 영역의 존재를, 가림 뒤에 Actor가 있다는 주장과 구분하십시오. 보이지 않는 Actor나 측정할 수 없는 영역의 geometry를 만들어내지 마십시오.
최종 JSON에서 근거 ID와 역할, 관계 상태, 대응 조건과 based_on이 확정된 규칙에 맞는지 확인하십시오. 사진별 정답이나 C polygon은 제공되지 않습니다. 기존 Schema와 enum을 변경하지 마십시오.
```

GT 객체 목록, C, Draft 정답 상태를 입력에 넣지 않습니다. Parser가 예측 상태를 자동 수정하거나 근거를 보충하지 않습니다. 관측할 수 없는 Region geometry는 팀에서 확정할 R3·Schema의 표현 범위에 따르며 임의 Box를 만들지 않습니다. 원본 이미지를 다시 확인하는 과정에서도 GT, C 또는 정답 ID에 접근하지 않습니다.

## 필요한 사례와 후속 학습 준비

| 사례군 | 구분할 내용 | 사람 검수 항목 |
|---|---|---|
| R3=P와 R3=A | 차량 존재가 곧 가림은 아니며 가림이 곧 숨은 Actor 존재도 아님 | 가림 객체, 관련 영역, 측정 가능한 geometry, 관계 근거 |
| R2=U와 R2=A | 경계·접지가 불명확한 경우와 충분히 관측한 뒤 관계가 없는 경우 | 출입구의 도로 연결, 보이는 Actor, 위치와 정보 범위 |
| 같은 객체의 여러 관계 | 점유·가림·통행 공간 제약의 동시 성립 가능 | Object/Region 역할과 관계 ID의 일관성 |

공통 6장은 흐름 확인과 오류 예시 보완에 사용하며 성능 향상을 독립적으로 증명하기에는 부족합니다. 별도 Dev는 P/A/U와 음성 사례를 포함하고 후속 Train과 source_group 단위로 분리합니다. 향후 QLoRA를 진행한다면 검수한 사례를 동일 JSON target 형식으로 구성하고 입력과 target을 분리합니다. Prompt/image/padding은 지도학습 loss에서 제외합니다. 학습량은 실제 검수 가능량에 따라 정하며 이미 확보한 것처럼 수치를 만들지 않습니다.

## Dev 평가와 판단 기준

모든 비율은 분자와 분모를 함께 표시합니다. 분모가 0이면 N/A와 사유를 적습니다. 아래는 향후 Dev 평가 약속이며 현 샘플 평가기에 모든 생산 지표가 구현되어 있다는 뜻은 아닙니다.

| 진단 항목 | 분자 / 분모 |
|---|---|
| R3 P recall | P로 예측한 검수 완료 R3=P 장면 / 전체 검수 완료 R3=P 장면 |
| R3 오탐 | P로 예측한 검수 완료 R3=A 장면 / 전체 검수 완료 R3=A 장면 |
| R2 U recall | U로 예측한 검수 완료 R2=U 장면 / 전체 검수 완료 R2=U 장면 |
| R2 과도한 U | U로 예측한 검수 완료 R2=P 또는 A 장면 / 전체 검수 완료 R2=P 또는 A 장면 |
| 관계 상태 정답 | 상태가 맞는 관계 항목 / 검수 완료 및 적용 가능한 전체 관계 항목 |
| 근거 매칭 | 기하 매칭 후 근거 집합·역할이 맞는 관계 항목 / 검수 완료이며 근거 측정이 가능한 적용 대상 P/U 관계 항목 |
| 첫 JSON / Schema 유효 | 첫 응답이 해당 검사를 통과한 요청 / manifest의 전체 요청. 두 비율 별도 보고 |
| Action 통과 | 고정 대응 규칙을 충족한 장면 / 대응 reference 검수가 완료된 적용 대상 장면 |

의미적 진단에서도 실패 요청 수를 보고합니다. Invalid/Timeout의 FN 처리, 오탐 분모와 대응 실패 처리는 팀 공통 지표에서 확정하고 같은 버전을 A/B에 대칭 적용합니다. 실패를 조용히 제외하지 않습니다. 유효 응답 부분집합을 추가 보고한다면 분모를 명시하고 전체 Benchmark로 부르지 않습니다. 근거 geometry 측정 불가, Missing, 미검수, 비적용을 따로 표시하며 IoU를 만들거나 U와 혼합하지 않습니다.

같은 Dev 장면으로 A/B를 짝지어 비교합니다. 먼저 샘플과 라벨을 고정한 뒤 첫 응답을 모두 저장합니다. Prompt별 run_id를 구분하며 다음을 함께 확인합니다.

- R3 P recall과 A 장면 오탐을 함께 확인합니다.
- R2 U recall과 판단 가능한 장면의 과도한 U를 함께 확인합니다.
- 기하 매칭 후 근거 ID·역할 일치와 관계 상태 정답을 별도로 평가합니다. Region geometry 측정 불가는 별도로 표시합니다.
- First-pass JSON/Schema 유효율, 실패 및 재시도 수를 기록합니다.
- 필요 대응 충족, 미허용·금지 대응, 관계와 조건의 일관성을 구분합니다.

공식 V5는 검수와 12개 관계·상태 조합 확보 조건을 충족해야 하며 그렇지 않으면 N/A입니다. 소규모 Pilot은 사례별 차이와 분모를 보고하고 유의한 전체 개선을 주장하지 않습니다. 충분한 독립 source_group을 확보한 뒤 그룹 단위 paired 신뢰구간 분석을 고려합니다. 최종 Test는 Prompt와 설정을 고정한 뒤 사용합니다.

## 선행 조건과 산출물

먼저 PDF와 샘플 패키지의 대응 규칙 차이를 해결하고 C, 객체 coverage, R2 경계와 R3 영역 geometry를 검수합니다. 규칙·GT 변경을 Prompt 변경과 한 실험에 섞지 않습니다. 라벨이 모호하면 검수 대기로 표시하고 모델 오류로 확정하지 않습니다.

금요일에는 이 실험안과 기존 실제 오류 증거를 제출합니다. 일요일 후속으로 `sample_id / GT와 예측 차이 / 실패 단계 / 확인 근거 / 다음 개선 작업` 오류표를 작성하고 두 오류가 여전히 우선 과제인지 검토합니다.

후속 실험 완료 시 A/B 각각 전체 고정 Prompt, run_id, 모델/데이터/라벨/규칙 버전, Dev manifest, 첫 raw/decoded/parsed, 실패 상태와 재시도 기록, 설정, 사례별 비교표와 분자·분모가 있는 지표표를 보존합니다. 모든 첫 실패를 남기고 재시도 중 가장 좋은 출력만 선택하지 않습니다.
