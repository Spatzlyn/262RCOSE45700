# Annotation Guideline · pilot-guideline-0.2-draft

이 문서는 통합 기획안의 R1–R4 정의를 샘플 Annotation에 적용하는 검수 기준입니다. 현재 샘플은 AI Draft이고 범위·기하·Class Coverage 검수가 끝나지 않았습니다. 문서의 규칙을 추가한 것만으로 기존 Label이 Reviewed가 되지는 않습니다.

## 1. 판정 범위와 객체 목록

평가 문항의 입력 View·Intent·Decision Time·대상 구간을 먼저 정합니다. F 문항에 B/L/R의 보이지 않는 정보를 가져오지 않습니다. 시간 순서가 없는 방향별 이미지로 Motion이나 미래 사건을 정답화하지 않습니다.

Object 후보는 보행자, 차량·이륜차·자전거, 가시 장애물과 별도 지정한 도로 시설물입니다. 형상과 개체 분리를 확인할 수 있는 대상을 Box로 기록합니다. 작은 크기만으로 제외하지 않되, Class나 개체 경계를 판독할 수 없으면 `review_candidates`에 위치·불확실성·검수 이유를 기록합니다. 이미 등장한 Source 객체와 새 후보가 같은 instance인지 확인한 뒤 추가합니다. 미관측 후보를 가상의 Object로 만들지 않습니다.

새 Box는 원본 좌표에서 실제로 보이는 대상의 범위입니다. 가려진 하체·차체 외형을 상상해 늘리지 않습니다. Pixel `[x1,y1,x2,y2]`를 이미지 너비·높이로 정규화하며 오른쪽·아래쪽 경계는 half-open입니다. 기존 Source의 Box와 RLE는 변경하지 않고, 보정이 필요하면 출처와 이유를 가진 별도 수정 이력을 남깁니다.

붙어 있는 적치물은 개별 경계가 불명확하면 연속된 `visible_cluster`로 기록합니다. 독립된 군집은 나눕니다. 봉투·포장물은 내용물을 추정하지 않습니다. 타고 있는 사람과 이륜차를 하나로 묶은 Source instance는 해당 정책을 명시하여 보존하고, 이륜차 옆에 따로 있는 사람은 별도 instance로 기록합니다.

## 2. 의미 역할·배치·가시성

| Field | 값·기준 |
|---|---|
| `semantic_role` | `actor`: 도로 이용 주체, `obstacle`: 고정 비행위자 장애물, `road_feature`: 도로 시설물 |
| `placement` | `roadside`, `travel_space`, `entrance`, `unknown` 중 영상에 보이는 배치 |
| `truncated` | 이미지 경계에 의해 대상이 잘리면 P, 전체 범위가 들어오면 A, 판독 불가이면 U |
| 가림 정보 | 다른 대상에 가려진 상태와 이미지 밖 잘림을 구분하여 기록 |
| 필드 검수 정보 | Source, Evidence, Status, Input Availability를 보존 |

`roadside`는 정차·주차 판정이 아닙니다. Single Image에서 Motion은 별도 근거가 없으면 Unknown입니다. 배달용 상자가 붙었다는 이유로 사람과 오토바이를 자동으로 합치지 않습니다.

`speed_bump`는 이 Pilot의 `road_feature`로 두고 R1 Actor/Obstacle 점유 대상에서 제외합니다. Object 저장 자체는 허용합니다. 이 제외는 R1의 평가 범위를 정하는 규칙이며, 주행 행동 전반에서 과속방지턱을 무시한다는 뜻은 아닙니다.

## 3. Driving Area C

C는 Intent와 도로 구조에 맞춰 지정하는 평가용 진행 영역입니다. 정밀 Ego Trajectory, 물리적 통과 가능 영역, 충돌 확률 영역이 아닙니다. 객체를 피해 경계를 굽히거나 원하는 R1 결과에 맞춰 폭을 바꾸지 않습니다.

동일 기준으로 재현할 수 있도록 다음을 Annotation에 남겨야 합니다.

| 결정 | 기록할 내용 |
|---|---|
| 좌우 폭 | 차도·분리 시설·노면 구분 등 기준이 되는 도로 경계와 관측 근거 |
| 공유도로 해석 | 중앙선 없는 도로에서 공유 진행 공간을 쓰는지와 적용 범위. 이미지 중앙에서 기계적으로 절반을 자르지 않음 |
| 가까운 종료점 | 자차 차체·이미지 경계 등 관측 시작 범위 |
| 먼 종료점 | 도로 구조를 구분할 수 있는 마지막 평가 구간과 종료 근거 |
| 가려진 경계 | 관측/추정/미확정을 구분하고, 근거가 없는 먼 구간을 확정 Polygon으로 연장하지 않음 |
| 경계 오차 | Pilot 그림에서 판정이 바뀌는 사례를 모아 허용오차와 U 기준을 확정 |

현재 `F_C`는 v0.1의 Polygon을 비교 기준으로 동결한 Draft입니다. 도로 전체 폭을 대표한다고 확정하지 않았고 폭·깊이 검수가 필요합니다. 좌표가 있으므로 자동 계산이 가능하다는 사실과 그 좌표가 검수된 정답이라는 사실을 구분합니다. 검수자가 C를 변경하면 모든 대상의 R1/R4와 관련 근거를 다시 확인하고 C 버전을 기록해야 합니다. 현재 C의 좌표는 모델 입력이나 예측 요구에 포함하지 않습니다.

## 4. Footprint와 R1

Footprint는 발·바퀴 등 지면 접촉 부분의 관측 투영입니다. Box 하단 선분이나 하단 중심은 Footprint와 동일하지 않습니다. Proxy를 사용하려면 별도 Pilot에서 오차와 적용 범위를 검증해야 합니다.

가시 접지점을 확인할 수 있으면 Object별 접지 좌표와 설명을 기록합니다. 점 좌표가 있다고 전체 Footprint Mask를 관측한 것처럼 표현하지 않습니다. 경계 오차나 가림으로 C 안/밖이 바뀔 수 있으면 대상별 U를 남깁니다.

현재 F는 `F_742187`, `F_742188`, `F_742189`, `F_742190`의 관측 타이어 접지점을 근거로 R1=P Draft를 구성합니다. 원거리 차량·사람의 관측되지 않은 접지는 U로 남깁니다. C 경계 검수는 이 접지 관측과 별도 단계입니다.

장면 R1은 명확한 P가 하나라도 있으면 P입니다. P가 없고 미해결 대상이 있으면 U, 평가 범위의 관련 대상을 충분히 확인해 해당하지 않으면 A입니다. 장면 P가 다른 대상의 U를 지우지는 않습니다.

## 5. R2·R3·R4

| Relation | P를 뒷받침할 근거 | 피해야 할 대체 판단 |
|---|---|---|
| R2 Entrance | 가시 Actor, 출입구 안/경계 관계, 해당 출입구와 C의 연결 | 사람이 건물 근처에 있다는 이유만으로 P |
| R3 Occlusion | 가리는 Object, 필요한 가려진 Region, 관련 진행 구간 | 가려진 Actor가 실제로 있다고 추정 |
| R4 Restriction | 제한하는 Object 배치, 영향받는 구간, 공간이 줄어든 근거 | C 비중첩만으로 제외하거나 길가라는 이유만으로 포함 |

출입구 후보 ROI는 확정 Entrance Polygon과 구분합니다. F의 추가 사람은 R2 근거 객체에 들어가지만 경계·연결 상태가 미해결이므로 R2=U를 유지합니다. 숨은 영역은 Occluder ID와 Region ID로 기록하되 정확한 범위를 관측할 수 없으면 Geometry를 `null`로 둡니다.

`F_742186`은 R4의 확정 근거 목록에서 검수 후보로 이동했습니다. 해당 C 구간을 어떻게 제한하는지 아직 충분히 특정하지 못했기 때문입니다. C와 Box가 겹치지 않는다는 사실을 일반적인 R4 제외 규칙으로 사용하지 않습니다. 실제 통과 폭·통과 가능 여부는 R4=P와 별개로 Unknown일 수 있습니다.

## 6. Sidewalk·색칠된 노면·통행 규칙

이 Pilot의 Sidewalk 검수는 도로와 구분되는 연속적인 보행 공간인지 확인하는 과정입니다. 점포 출입용 단차, 짧은 전면 공간, 색칠된 노면을 같은 것으로 자동 처리하지 않습니다. 물리적 분리 여부와 노면 표시·용도 지정을 별도 속성으로 기록하여 정의를 검수할 수 있게 합니다.

A는 실제 확인한 범위에만 적용합니다. 가까운 일부 구간에서 분리가 보이지 않는다는 관측을 차량 뒤와 먼 구간까지 확대하지 않습니다. F 전체 측면은 가림과 범위 문제로 좌우 U를 유지하며, 가까운 가시 구간의 관측은 별도 분석 속성으로 둡니다. 녹색 노면의 존재는 P지만 그 용도가 보행 전용인지는 U입니다.

Traffic Direction은 해당 도로에 적용되는 표지·규칙을 판독할 때만 확정합니다. 마주 보는 차량, Centerline 부재, 녹색 노면 자체를 One-way/Two-way의 근거로 쓰지 않습니다. Time of Day와 환경 분석 속성은 Reference Annotation에 유지하고 Track 1의 채점 대상 출력에는 요구하지 않습니다.

## 7. 근거 집합과 Action

Object Coverage는 평가 범위 내 대상 목록이 얼마나 완전한지를 뜻합니다. Relation의 충분 근거는 그 판정을 지지할 수 있는 허용된 ID·역할 집합을 뜻합니다. 이 둘을 분리합니다. R1=P의 근거를 항상 모든 겹친 객체로 열거하도록 강제하지 않고, 검수된 충분 근거 집합의 대안을 Reference에 기록합니다. 모델의 ID는 Class·위치 매칭을 통해 Reference ID로 대응시킨 후 근거 역할을 대조합니다.

역할에는 Actor, Obstacle, Occluder, Entrance, Occluded Region, Restricting Object를 명시합니다. Prediction의 근거 ID는 해당 Prediction에 선언된 Object/Region을 참조해야 합니다. C는 평가 전용 Reference이며 모델이 C의 정답 ID·좌표를 복사하도록 요구하지 않습니다.

| 조건 | 필수 대응 대안 |
|---|---|
| R1=P, Actor 점유 | `YIELD_IF_OCCUPIED` 또는 `HOLD_UNTIL_CLEAR` |
| R1=P, 고정 Obstacle 점유 | `HOLD_UNTIL_CLEAR` |
| R2=P | `MONITOR_AHEAD` 또는 `REDUCE_SPEED_IF_MOVING` |
| R3=P | `VERIFY_BEFORE_ADVANCE` |
| R4=P/U | `VERIFY_PASSAGE` |
| R1–R3 중 U | 해당 모든 U Relation을 `based_on`에 연결한 불확실성 확인 |

`roadside` 배치만으로 Actor의 R1 대응을 면제하지 않습니다. 길가 차량에 다른 대응을 적용하려면 별도의 규칙 개정과 검증이 필요합니다. R2가 나중에 P로 바뀌어도 R3=P의 가림 확인 요구는 남습니다. 서로 다른 조건의 필수 대응은 모두 충족해야 합니다.

## 8. 검수 상태와 평가 가능성

P/A/U는 장면에 관한 판단이며 Missing/Draft/Reviewed는 Annotation 완성·검수 상태입니다. Reviewed인 U는 정답이 될 수 있지만, Draft를 U로 바꿔 검수 완료를 대신할 수 없습니다. AI 검토만으로 `human_review_completed=true`를 기록하지 않습니다.

현재 검증기는 구조·참조를 검사하고 평가기는 라벨·Action과 위치·역할 매칭 진단을 제공합니다. 객체 범위와 Reference가 미검수인 현재 상태에서는 공식 V3/V4가 성립하지 않습니다. 이 샘플 평가기는 공식 V3/V4 집계를 구현하지 않았으며 `diagnostics.benchmark`의 두 값을 항상 `null`로 유지합니다. Reference 검수만으로 공식 집계 기능이 생기지는 않습니다. 숨은 Region처럼 관측 기하가 없는 항목은 ID 문자열·타입 일치만으로 기하 매칭 성공을 부여하지 않고 미평가 사유를 남깁니다.

정식 평가 전에 대상 Class·평가 영역, C, 객체 Coverage, 출입구와 가림 Region의 평가 표현, 허용 근거 집합, Action Rule을 독립 검수해야 합니다. 각 항목에 검수자·날짜·Guideline Version을 기록하고, 같은 Source Group의 방향별 이미지와 파생본은 동일 Split에 둡니다.
